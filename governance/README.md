# 운영 원칙과 역할

확정 방향: 비영리 운영, SHARE·MAKE·CONNECT, 회원의 GitHub 사용 비강제, 실제 모임 참가자만 비공개·실명제 단톡방 초대, 개인정보와 공개 자료 분리.

## 역할 배분 초안

| 역할 | 책임 | 지정 상태 |
| --- | --- | --- |
| Community Lead | 방향과 대외 관계 | 미지정 |
| Program Lead | 사례 발표·강의·핸즈온 기획 | 미지정 |
| Community Manager | 온보딩·규칙·신고 | 미지정 |
| Tech Lead | GitHub·실습 안전 | 미지정 |
| Content Curator | 동의·권리·공개 자료 검수 | 미지정 |

초기 위원회 4~5명과 역할 겸임은 제안이며 외부 초대는 수행하지 않았습니다. GitHub 관리자는 현재 serithemage입니다. 이는 위원회 전체의 선임을 뜻하지 않습니다.

## 의사결정 초안

공개 가능 여부 검토 → Discussion 의견 수렴 → 권한 있는 운영진 결정 → Decision Record → Issue·Projects 실행 → PR 검토 → 공개 가능한 결과 게시.

추천 수와 투표 결과는 참고 자료입니다. 의결 정족수, 비용 승인 한도, 위원 선임은 별도 확정해야 합니다. 이해관계가 있는 운영위원은 해당 결정에서 제척하며, 비용 승인과 신고 처리는 상호 검토합니다. 미확정 정책은 승인된 정책으로 표시하지 않습니다.

중요 정책 PR은 이해관계가 없는 운영진의 검토 후 병합합니다. 현재 단일 관리자이므로 독립적인 승인 리뷰를 구현할 수 없습니다. 초기 인프라 PR의 관리자 병합은 사용자 구축 승인에만 근거합니다. 실제 정책 의결은 후속 운영 과제입니다.

비영리 운영은 법인·지정기부금단체 지위 취득을 뜻하지 않습니다. 후원은 프로그램 편성과 도구 선택의 독립성을 제한하지 않습니다. AWS 장소·실습 환경 지원의 세부 조건과 대외 표기·로고 사용은 별도 확인하며 이 저장소에서 로고를 사용하지 않습니다.
